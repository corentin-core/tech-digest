⭐ Le pick de la semaine

rust Deser : repenser la sérialisation en Rust · lucumr (Armin Ronacher) · ~14 min · lien Ronacher expose trois limites de fond de serde (perte de précision au buffering, adaptateurs non composables, récursion sur la pile qui ouvre un déni de service) et propose une architecture inversée : le format émet des événements vers des « puits » sur le tas, ce qui rend la désérialisation suspendable et sans débordement de pile. → Pour toi : c’est pile ta forme de problème — aller-retour de sérialisation, conversions de types, trames parfois reçues en morceaux. Le modèle « suspendable » parle directement à un parseur qui doit reprendre là où une trame s’est arrêtée.

📚 À lire

  1. rust Rusty thoughts on “Parse, don’t validate” · Eli Bendersky · ~6 min · lien Plutôt que vérifier une condition et espérer qu’on s’en souvienne plus loin, on fabrique un type qui encode l’invariant (NonEmpty<T>, AbsPathBuf, NonZero) : une fois la donnée transformée, le compilateur garantit la propriété pour toujours. Court, net, exemples tirés de rust-analyzer. → Pour toi : l’esprit même de ta bibliothèque Rust — faire porter l’invariant par le type au lieu de revalider partout.

  2. langage We Have Named Arguments at Home · corrode.dev · ~10 min · lien Rust n’a pas d’arguments nommés ; l’article montre qu’on n’en a pas besoin : struct de paramètres, Option/Default, traits, enums couvrent chaque cas, avec documentation et vérification de typo en prime. Défense soignée du design par contraintes plutôt que par ajout de syntaxe. → Pour toi : du design d’API au quotidien — l’arbitrage struct/enum/trait contre une rustine syntaxique, exactement ce qu’on tranche en dessinant une surface propre.

  3. rust Rust Reborrowing, Aliasing, and Mutable References · developerlife.com · ~18 min · lien Explique proprement le reborrow (le compilateur insère &mut *ref pour créer un emprunt enfant temporaire), les lifetimes non lexicales, et la frontière entre délégation séquentielle valide et aliasing concurrent interdit. Analogies physiques, diagrammes, correction des idées fausses courantes. → Pour toi : si tu apprends Rust activement, ça clarifie le moment exact où un &mut est « mis en pause » puis rendu — une source classique de bagarre avec le borrow-checker.

  4. archi Domain–Flow–Effects (DFE) : une architecture pensée pour Rust · codigolinea.com · ~18 min · lien Après 20 ans d’OOP, l’auteur raconte pourquoi plaquer Clean/Hexagonal sur Rust crée de la complexité inutile, et propose trois couches : Domain (règles pures), Flow (coordination), Effects (I/O). Couplage explicite assumé, abstraction seulement quand elle paie. (En espagnol, code en Rust — lisible.) → Pour grandir : ça t’ouvre vers l’archi de systèmes — structurer la complexité d’un service sans couches qui se battent avec le langage.

  5. craft Git 3.0’s upcoming SHA-256 default will be a costly mistake · gitbutler (Scott Chacon) · ~17 min · lien Chacon soutient que basculer le hash par défaut de Git vers SHA-256 coûte cher (outillage cassé, écosystème scindé en dépôts incompatibles) pour un gain quasi nul, puisque la confiance vient de « d’où tu tires », pas de la force du hash. Propose une alternative : un en-tête SHA-256 optionnel sans remplacer le stockage. ⚠️ Le titre dramatise : « train wreck » suppose le résultat plus qu’il ne le démontre — le vrai sujet est le coût de coordination, pas une catastrophe inévitable. → Pour toi : un raisonnement coût/bénéfice de migration d’un format pivot — transférable à tout changement qui casse l’aval.

  6. devtool Rust’s derive often implies inline · yossarian.net · ~4 min · lien #[derive(...)] pose des #[inline] sur le code généré (p. ex. Debug) ; sur des types d’erreur profondément imbriqués, le compilateur inline sans limite et gonfle le binaire. uv a gagné ~160 Ko avec un #[inline(never)] ciblé. → Pour toi : sur cible Linux contrainte, 160 Ko en moins pour une annotation — le genre de détail qui compte quand l’espace est compté.
