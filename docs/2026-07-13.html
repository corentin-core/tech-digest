⭐ Le pick de la semaine

rust Rewriting Bun in Rust · Bun · ~25 min · lien Jarred Sumner explique pourquoi Bun (moteur et boîte à outils JavaScript) migre de Zig vers Rust : douze bugs de stabilité (accès après libération, double libération, fuites) nés du mélange entre valeurs gérées par ramasse-miettes et mémoire libérée à la main — que le defer de Zig ne suffisait pas à discipliner. Le billet est honnête sur les compromis (port mécanique d’abord, unsafe résiduel pour les dépendances C/C++) et chiffre les gains (~20 % de binaire en moins, 2-5 % de perf). → Pour toi : c’est exactement la douleur du cycle de vie mal maîtrisé — nettoyage oublié avant la fin, ressource « crue libérée » — mais résolue en la faisant porter par le type (Drop) plutôt que par la discipline. Le cœur de ce qui te plaît en Rust, sur un vrai cas de production.

📚 À lire

  1. rust Closing a three-year-old issue using Rust arenas · giacomocavalieri.me · ~12 min · lien Un mainteneur de Gleam remplace les Box récursifs de son imprimeur de code (pretty-printer) par des références dans une arène (allocateur qui range tout dans un bloc et libère d’un coup) : formateur nettement plus rapide, ~10 % de pic mémoire en moins. Belle démonstration de refonte de structure de données guidée par les lifetimes. → Pour toi : de la conception mémoire concrète — quand une structure récursive coûte cher, changer la propriété des nœuds plutôt que micro-optimiser. Pile ta voie archi/design croisée avec Rust.

  2. rust Typed MQTT topics for Rust (mqtt-typed-client) · holovskyi.github.io · ~8 min · lien La bibliothèque transforme un motif de topic MQTT (sensors/{location}/{sensor_id}/temperature) en struct typé via macro procédurale : plus d’inversion de paramètres silencieuse, un désaccord de type devient une erreur de compilation, et le motif est défini à un seul endroit. Honnête sur ses limites (embarqué à budget d’allocation, topics vraiment dynamiques). → Pour toi : exactement ta forme pub/sub MQTT avec l’invariant porté par le type. Le genre de surface d’API transposable à une carte de registres ou un aller-retour de sérialisation pour tuer les bugs de câblage dès la compilation.

  3. craft Two case studies of NaN · sebsite.pw · ~5 min · lien Deux bugs réels dus au NaN (valeur flottante « pas un nombre ») : [nan] == [nan] vaut True en Python (la comparaison teste l’identité d’abord), et les boucles for numériques de Lua font n’importe quoi parce que < et <= sont mélangés selon l’étape. Leçon transférable : le code suppose partout qu’un objet est égal à lui-même — faux pour NaN, et le détail d’implémentation finit par fuir dans le comportement visible. → Pour toi : piqûre de rappel sur la correctness — un cas spécial non traité explicitement se manifeste en aval, là où on ne l’attend pas.

  4. craft Good Tools Are Invisible · Ginger Bill · ~7 min · lien L’auteur du langage Odin défend l’idée qu’un bon outil s’efface : de bons réglages par défaut valent mieux qu’une configurabilité infinie, et le sentiment d’être productif (résoudre des puzzles dans son éditeur) n’est pas la productivité — le vrai test, c’est le temps au mur. ⚠️ La charge contre vim/emacs frôle l’homme de paille — prends l’argument, pas le règlement de comptes. → Pour toi : nourrit ton goût du craft et de l’outillage — le jugement de conception, pas l’outil pour l’outil.

  5. IA Claude Code sends 33k tokens before reading the prompt; OpenCode sends 7k · systima.ai · ~17 min · lien Mesure au niveau de l’API (un proxy qui journalise, avec chaîne de hachage pour l’auditabilité) du « coût fixe » — prompt système, schémas d’outils — envoyé avant ta requête, entre deux agents de code. ⚠️ Le titre survend : le 4,7× ne vaut que pour la 1re requête avant mise en cache, tombe à ~3,3× sur Fable 5, et le cache en absorbe une bonne partie ; le vrai sujet, ce sont les sessions multi-tours et la réécriture du préfixe. → Pour toi : méthodo de profilage de bout en bout — mesurer à la vraie frontière (l’API) plutôt que croire les logs applicatifs. Ta forme « descendre d’une couche quand l’aval voit autre chose ».

  6. rust Work In Progress Rust · blog.dureuill.net · ~10 min · lien Un ingénieur de Meilisearch propose une petite crate wip (macros wip!, unwrap_wip, fixme!) : coder la logique d’abord en émettant des avertissements au lieu de bloquer sur la gestion d’erreur, puis nettoyer avant de fusionner (CI en -D warnings). ⚠️ Rien de révolutionnaire — on diffère la gestion d’erreur depuis toujours — mais l’outillage est propre et bien pensé. → Pour toi : pratique quand tu prototypes une tâche async et veux itérer sur le flux avant de durcir l’annulation et le nettoyage.

🚀 Stretch — bonus, si tu as le temps

Ambitieux mais lisible.
