⭐ Le pick de la semaine

rust Rusty thoughts on “Parse, don’t validate” · eli.thegreenplace · ~7 min · lien Le vieux principe « transforme la donnée en un type qui garantit l’invariant, au lieu de la re-vérifier partout » appliqué à Rust, exemples réels à l’appui (NonEmpty<T>, AbsPathBuf de rust-analyzer, NonZero, serde). Une fois la donnée passée dans le type raffiné, plus aucun contrôle à l’exécution : le compilateur s’en charge. → Pour toi : c’est exactement l’esprit que tu travailles en Rust — faire porter l’invariant par le type. Une trame de protocole « crue complète » qui ne l’est pas devient un bug de moins si « trame complète » est un type qu’on ne peut construire qu’à partir d’octets validés.

📚 À lire

  1. craft Finding Bugs · matklad · ~9 min · lien Comment un fuzzer (générateur de cas de test aléatoires) confronté à un oracle (une implémentation de référence connue correcte) déniche des bugs même dans du code très testé — démonstration sur la crate regex. La leçon : co-concevoir le code et son harnais de test donne un levier énorme. ⚠️ Le titre est générique : ce n’est pas un guide de débogage, mais une méthode précise de test par propriétés contre un oracle. → Pour toi : un aller-retour Protobuf est un oracle gratuit — sérialiser puis désérialiser doit redonner l’entrée. Même logique pour un parseur de trames : génère des trames, compare au décodeur de référence.

  2. langage Arguing about arguments · Steve Klabnik · ~12 min · lien Klabnik revient sur son opposition aux paramètres nommés en Rust : il distingue paramètres nommés, arguments optionnels et surcharge, et explique pourquoi les noms au site d’appel aident la lisibilité (et les agents de code). Une bonne leçon de design de langage et des compromis d’ergonomie d’API. → Pour toi : dans un pilote piloté par configuration où l’appel empile des paramètres (carte de registres, réglages), le nommage au site d’appel est précisément le compromis qu’il dissèque.

  3. IA Plan mode is dead · Ayman Nadeem · ~6 min · lien L’auteur a bâti un outil autour d’un « mode plan » explicite, puis a constaté que le document de spec rigide colle mal à la façon dont on pense vraiment : mieux vaut une boucle comprendre → agir → inspecter → ajuster. Réflexion utile pour piloter des agents de code au quotidien. ⚠️ Titre putaclic : le plan n’est pas « mort », c’est le document de plan figé qui l’est ; planifier reste utile. → Pour toi : directement transférable à ta façon d’utiliser Claude Code — la boucle itérative plutôt que le tunnel spec → approbation → build.

  4. devtool Small and secure Docker images for Rust: Alpine vs Debian vs Scratch · kerkour.com · ~4 min · lien Comparaison chiffrée des trois bases (scratch 3,4 Mo, Alpine 11 Mo, Debian slim 77 Mo) avec les compromis : liaison statique musl vs dynamique glibc, surface d’attaque, complexité de build. Recommandation : scratch par défaut (musl impose de changer d’allocateur type MiMalloc pour la perf). → Pour toi : touche ton terrain packaging/déploiement — le choix musl/glibc et la liaison statique sont exactement les arbitrages d’un binaire Rust qu’on livre sur cible.

  5. c++ Writing Efficient C++ Code · asawicki.info · ~9 min · lien Un tour d’horizon qui part du design (conception orientée données, tableau de structures vs structure de tableaux) et descend vers la hiérarchie mémoire. Le principe transférable : structurer autour de la donnée et de son agencement mémoire est une décision de conception, pas une optimisation tardive. ⚠️ Ça plonge dans les cache lines et le coût des instructions — la partie qui te laisse froid ; lis-le pour l’angle conception (agencement des données), pas pour les micro-astuces. → Pour toi : ouvre ta voie C++ moderne côté archi — penser l’agencement mémoire au moment du design.

🚀 Stretch — bonus, si tu as le temps

  • perf Tuning a Server for Benchmarking · david.alvarezrosa · ~5 min · lien — Comment faire tomber la variance de mesure de ~3 % à 0,26 % par étapes cumulatives (épinglage sur un cœur, gouverneur de fréquence, désactivation de l’hyperthreading et du turbo). Chaque étape est chiffrée et reproductible. → Pour grandir : c’est la discipline « lire en variance, pas en moyenne » appliquée à la mesure elle-même — le socle méthodo pour raisonner p99/déterminisme sur une boucle de contrôle. Ambitieux mais court.
