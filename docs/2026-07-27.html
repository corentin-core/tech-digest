⭐ Le pick de la semaine

async Tokio Gives Progress, Not Ordering: Scheduling 1M Tasks · pranitha.dev · ~9 min · lien Un service qui éclate ~1M de tâches courtes croyait que « soumises tôt = démarrées tôt » ; les logs montrent des tâches des premiers événements réveillées bien plus tard. L’auteur descend dans l’ordonnanceur Tokio (une file locale de 256 par worker, une file globale, vol de tâches entre workers) pour expliquer pourquoi la file d’attente réordonne tout — c’est concret, pas théorique. → Pour toi : c’est exactement le piège « le débit tient, mais la queue de latence ment ». Ta vraie question n’est jamais la moyenne mais la tâche qui dérive loin de son ordre de soumission — à lire en p99, pas en moyenne, comme un cycle qui déborde ponctuellement.

📚 À lire

  1. rust Hardening Rust Code For Production · corrode.dev · ~13 min · lien Check-list concrète pour durcir un binaire Rust en prod : comportement des panic (dérouler vs. abandonner), hook de panique pour l’observabilité, arrêt propre, sondes liveness/readiness (vivant vs. prêt à servir), et nettoyage des secrets dans les messages d’erreur. Des exemples réels, pas du remplissage. → Pour toi : un service de fond longue durée (acquisition → calcul → publication) vit ou meurt sur ces détails — arrêt propre des tâches, et surtout scrubbing des secrets avant qu’ils ne fuitent dans une archive de diagnostic.

  2. rust Capture Clauses as Effects · yoshuawuyts (blog) · ~13 min · lien Proposition de langage pour rendre la capture de variables dans les closures moins pénible : au lieu d’empiler dix let x = foo.x.clone(); avant un spawn, un with own(...) déclarerait la capture comme un effet. Exploratoire et honnête sur ses zones d’ombre, mais c’est du Rust-langage au meilleur niveau. → Pour toi : la danse « je clone tout ce dont la tâche a besoin juste avant de la lancer » est ton quotidien async ; ça montre comment on peut faire porter cette intention par le langage plutôt que par la discipline manuelle.

  3. rust Two Bugs I Only Found Running My Rust Daemon Against Real Infrastructure · dev.to · ~4 min · lien Deux bugs qui ne sortent qu’au contact du réel : (1) l’en-tête d’autorisation silencieusement supprimé par reqwest sur une redirection HTTP→HTTPS ; (2) un code HTTP 200 pris pour preuve de succès alors que le traitement est asynchrone côté serveur — le résultat réel n’arrive jamais. Court et net. → Pour toi : le bug n°2, c’est ta forme « état cru terminé qui ne l’est pas » — un résultat async avalé, le OK renvoyé avant que l’aval ait vraiment fini. Le réflexe : ne jamais confondre « la requête est partie » et « l’opération a abouti ».

  4. devtool Delightful Integration Tests in Rust · rust-magic-patterns · ~9 min · lien Pattern propre pour des tests d’intégration isolés : testcontainers lance un vrai conteneur (Postgres, RabbitMQ…) par test, et le trait Drop de Rust nettoie tout à la fin du scope — chaque test a son environnement neuf, sans fichier docker-compose externe, dans le flux cargo test habituel. → Pour toi : la même idée vaut pour tester des pilotes pilotés par config contre un faux équipement (un serveur Modbus/TCP jetable) : isolation par test, montée en condition attendue, nettoyage garanti par le RAII.

  5. c++ The Perils of Parsing Type Inference Declarations in C · sebsite.pw · ~6 min · lien auto peut être soit une classe de stockage, soit un tenant-lieu de type selon le contexte — et quand un typedef de même nom traîne dans un scope englobant, GCC et Clang ne parsent pas pareil. Une plongée courte dans une ambiguïté grammaticale bien réelle. → Pour toi : tu écris du C++17/20 truffé d’auto ; ça rappelle que l’inférence de type n’est pas gratuite pour le compilateur, et pourquoi deux compilateurs peuvent diverger sur du code « évident ».

🚀 Stretch — bonus, si tu as le temps

  • stretch Maybe We Should Revisit Microkernels · notes.hella.cheap · ~5 min · lien — L’argument : les microkernels étaient trop lents dans les années 90 à cause des changements de contexte, mais l’IOMMU (unité de traduction d’adresses matérielle) et la mémoire partagée permettent aujourd’hui de les éliminer du chemin nominal (files circulaires + compare-and-swap atomique pour l’IPC). Argumenté par l’ingénierie, pas l’idéologie. → Pour grandir : court mais dense, ça t’ouvre vers l’archi systèmes sous contrainte — séparer les responsabilités sans payer la latence, exactement le raisonnement que demande le temps réel. Ambitieux si les entrailles noyau te sont peu familières, mais c’est la bonne direction.
